## 1. Overnight expectations

Supportive (what good looks like by morning):

- Beats hold firm: 0 timers fire, no GPU contention, operator's studio
  idle or active undisturbed either way.
- Beads: `hngh-4ym` gets its uro verdict (or waiver), `hngh-7hj` ACP
  probes advance read-only, `hngh-npi` contexts redesign drafts.
- Tree stays clean: gitignore holds, no new residue, ledger sync only.
- Morning digest carries its first Jev triage block whenever timers
  return (wired, fail-open, waiting).

Adversarial (what could be true instead):

- A timer re-enables itself via preset (systemd `preset: enabled`
  noted on the 30m unit) — mitigated: units read `disabled`, but
  verify after any `daemon-reload`.
- Verdict file goes stale (`tmp-beatskip.txt` 30s cache + midnight
  gate): a beat could read `keep` from an idle afternoon during an
  active night. Mitigated: fail-open design means worst case is a
  routed-to-kimi call, never a local eviction — but the reroute costs
  quota. Watch: first beat after resume logs its verdict age.
- Worker drift: swarm workers on the 1024-plan keep completing against
  stale artifacts. Mitigated: completion reports carry file:line; the
  coordinator verifies before closing beads.

## 5. Field survey + Hngh position

Field (May 2026 three-way + Sep 2026 Jev wave): OpenClaw (375K★,
assistant platform on Pi SDK, 25+ channels), Hermes (171K★, gateway +
closed skill-learning loop, serverless), Pi (57K★, embeddable SDK +
supply-chain rigor), LangChain (middleware model: ModelRouter +
AutoMode = Jev-shaped), browser-use/jev-ultrafast (5.5k★, speculative
fan-out), jev-review (staged pipeline + dep-direction-as-code),
HKUDS nanobot (ultra-light), karpathy/autoresearch (orchestrator).

Hngh brings what they lack: kernel ceremony (governed mutation with
attestations — nobody else has this), beads bloodstream (git-native
issue memory with evidence close-out), Jev reflexes wired into the
loop (not bolted on), fail-open guard posture throughout, Unsloth-local
hardware harnessing (own GPU as first-class leg), city-state
self-model (the system reads itself to itself).

They bring what Hngh lacks: channels (OpenClaw 25+ vs our zero),
gateway (Hermes multi-platform presence), closed skill loop
(Hermes learns SKILL.md from experience — we should steal this),
embeddable SDK shape (Pi), ultra-light mode (nanobot), ecosystem
(community size, integrations, docs).

OpenClaw parity verdict: YES on harness capability (loop, tools,
models, memory, guards), NO on channels (and deliberately so —
the operator is not asking for 25 messaging integrations), AHEAD on
governance (ceremony), memory-as-bloodstream (beads), and reflexive
judgment (Jev). Do not chase feature parity; chase the positioning:
the self-governing hardware harness that gets smarter overnight.
That is a category the field does not have.
