# SWE / Self-Improving Agent Systems — Research for Hngh

Research date: 2026-08-07 · Agent: delegated Hermes subagent (deepseek-v4-flash) · Source for autonomy-strategy.md §1.

Every claim tied to a cited source; third-party-reported numbers flagged as such; uncertainty flags in the final section.

---

**OpenAI Codex** — OpenAI's engineering post "Unrolling the Codex agent loop" is the most explicit primary source on harness design: prompt → inference → tool call → append output → re-query, repeating until the model emits a final assistant message. Three hard-earned lessons from it: (1) **context grows every turn** — an agent can make hundreds of tool calls in one turn and exhaust the window, so context-window management is a first-class harness responsibility; (2) they added a built-in `update_plan` tool so the agent maintains an explicit plan artifact mid-task; (3) they now auto-compact via a `/responses/compact` endpoint that preserves a latent summary when a `auto_compact_limit` is exceeded. https://openai.com/index/unrolling-the-codex-agent-loop/
Cloud Codex adds the sandbox discipline: one isolated, internet-free sandbox per task, run the repo's tests in a loop until green, return a PR with the full command log. Third-party reporting (The AI Engineer) puts codex-1 at 72.1% SWE-bench Verified single-attempt, 83.8% with up to eight tries — *not* an OpenAI-published figure, treat with caution; the qualitative design claims match OpenAI's own docs. https://theaiengineer.substack.com/p/how-openai-codex-works

**Claude Code** — Anthropic's containment post is the best public data on the *supervision vs. autonomy* tradeoff: per-action approval prompts fail because users approved ~93% of them (approval fatigue), so they built "auto mode" (a model classifier that catches ~83% of overeager behaviors before execution while blocking only ~0.4% of benign commands — ~17% of risky actions still get through; it's defense-in-depth, not a guarantee). Their architecture pattern: **containment at the environment layer first** (sandboxes, devcontainers for unattended runs), model-layer steering second, and hooks for deterministic policy at tool boundaries. https://www.anthropic.com/engineering/how-we-contain-claude
Hooks (official docs) are the most directly transplantable mechanic: `PreToolUse` (can block/modify a tool call before it runs — your cost gate belongs here), `PostToolUse` (can inject `additionalContext` or rewrite tool output before the model sees it), `PostToolUseFailure`, `PostToolBatch`, `Stop`, `SubagentStop`. Exit-code 2 from a hook = block/deny. https://code.claude.com/docs/en/hooks

**OpenHands** (ex-OpenDevin) — event-stream architecture: every agent-environment interaction is a typed event through a central `EventStream` pub/sub hub; the newer SDK paper describes the productionized version: **event-sourced state with deterministic replay** (audit + rerun), immutable agent configuration, typed tool system with MCP, native sandboxed execution, model-agnostic multi-LLM routing. Their production data: V1 cut system-attributable failures vs. V0 with "negligible event-sourcing overhead." Lesson: an append-only event log is both your audit trail and your debugging substrate — your existing beans/event-bus design is the right call. https://arxiv.org/abs/2511.03690

**AutoGPT** — the canonical negative example: open-ended goal loops with no cost awareness, no step limits, no verifier. Documented community failures include infinite action loops and GitHub issue #6 ("Make Auto-GPT aware of its running cost"); the awesome-agent-failures case study's conclusions (resource limits mandatory, human oversight necessary) are echoed in every production postmortem. Third-party cost-blowup illustrations ($50k-class loops, fleet math) are blog-reported, not audited, but the mechanism — *an agent interpreting a changing timestamp as "progress" and looping forever* — is the exact pathology your hard cost gate must kill. https://github.com/vectara/awesome-agent-failures/blob/main/docs/case-studies/autogpt-planning-failures.md

## 2. Self-healing systems engineering

- **The canonical loop is MAPE-K style: monitor → diagnose → repair → verify → feed back.** The "Self-Healing Software Systems" survey (arXiv 2504.20093) describes a CI/CD-integrated prototype: on build failure/test crash it collects logs+diffs, prompts an LLM with the error, applies the candidate fix on a temp branch, runs verification, **reverts the fix up to three times on failure, then escalates** — with regression tests as the guard that a patch didn't break something else. It also notes GenProg-class tools fix syntax but struggle with semantics, and that LLM repairs need verification or they "generate syntactically valid but wrong" patches. https://arxiv.org/pdf/2504.20093
- **Runtime self-healing ≠ code self-healing.** Container/pod auto-restarts and chaos-failure reruns are mature and reliable; the *hard* part is autonomous source repair, because the fix must be verified against intent, not just "build passes." https://stackoverflow.blog/2023/12/28/self-healing-code-is-the-future-of-software-development/
- **Flaky-test protocol:** rerun under controlled conditions to confirm flakiness before "fixing" it — otherwise the agent chases noise and can burn a budget on a test that was never the bug.
- **Known failure mode:** self-modifying software can enter repair loops or produce unintended side effects without strong semantic awareness — the paper's authors explicitly flag repair-loop risk. That's an argument for *bounded retry + semantic tests*, not unbounded repair.

## 3. What "self-improvement" is actually practical in production

- **Reflexion (self-debugging via verbal reflection)** — the most practical research pattern: don't update weights; after a failed trial, have the agent *write a reflection on what went wrong and why*, store it in an episodic memory buffer, and feed it into the next trial. 91% pass@1 on HumanEval (vs 80% GPT-4). This is exactly "squad tests and regenerates fix" with a mandatory reflection artifact between attempts. https://arxiv.org/abs/2303.11366
- **Self-Debugging (Chen et al.)** — iterate *until tests pass or max turns*, feeding back execution results; rubber-duck explanation feedback (explain the code, find the bug) even works without unit tests. Up to +12% accuracy; importantly, **reusing failed predictions makes the loop sample-efficient** — you don't need N fresh generations, you need one generation + K cheap repair turns. https://arxiv.org/abs/2304.05128
- **Agentless** — the strongest counter-evidence to "more agent autonomy = better": a *fixed* pipeline of hierarchical localization (tree → files → functions → edit locations) → repair via sampled Search/Replace diffs → patch validation with generated reproduction tests + regression tests, with **no agentic decision-making at all**, beat all open-source agent frameworks on SWE-bench Lite (32% at $0.70 avg cost) at the time. Performance plateaued at ~40 patch samples. Lessons: staged pipelines are cheaper, more interpretable, and often better than free-form loops; **the verifier (reproduction + regression tests) is what makes sampling viable**; localization is where effort pays off most. https://arxiv.org/abs/2407.01489
- **MetaGPT** — "assembly line" multi-agent: SOP-defined roles (PM → Architect → Project Manager → Engineer → QA) where each stage emits a *structured intermediate artifact* (PRD, design doc) that becomes the next stage's input. The artifact hand-off is the key mechanism — it gives the pipeline a deterministic spine and makes failures attributable to a stage. https://arxiv.org/abs/2308.00352
- **aider** — practical harness patterns: (1) **tree-sitter repo map** so the model sees structure (signatures, symbols) without loading whole files — cheap context control; (2) **architect/editor split** — a strong (expensive) planner model + a cheap editor model for the edits, cutting session cost; (3) every change lands as an atomic, message-committed git commit — your git-backed dispatch trees already encode this. https://github.com/aider-ai/aider
- **GPT-Engineer** — clarify → scaffold loop (spec in, generated codebase out). It's a one-shot scaffolding generator, *not* a self-improving loop; its "self-improvement" is the human prompt-refinement cycle. Fine as a pattern for "planner produces spec → squad implements," but don't look to it for test-gated iteration. https://github.com/AntonOsika/gpt-engineer

## 4. Pitfalls every harness must engineer against

- **Runaway retry loops** — agent re-fixes a failing test, sees a different timestamp in the error, reads it as "progress," loops. Countermeasures seen in production: hard step counts, per-run/per-week budget caps with circuit breakers, "no progress = escalate" detection (same failing test N times → stop), and *reflection-artifact diffs* (if trial k+1's plan is textually near-identical to trial k's, it's looping).
- **Cost blowups** — every major system treats cost control as harness-level, not model-level: sandbox-per-task with staged dependencies (Codex), cheap-model-for-edits (aider architect mode), sample caps with diminishing returns (Agentless plateaued at ~40 samples).
- **Regressions** — the only reliable guard is a verifier richer than "the failing test passes": run the pre-existing test suite (PASS_TO_PASS) and reject patches that break it (Agentless's regression-test filtering, and the self-healing prototype's revert-up-to-3-then-escalate rule). Never accept "target test green" as completion.
- **Context overflow** — conversations grow every turn (Codex's explicit warning); countermeasures: compact/summarize old turns, keep the ACI terse (SWE-agent drops repeated error messages), feed structure/skeletons not whole files (aider repo map, Agentless skeleton format), and make reflection text the *compressed* artifact that survives across trials (Reflexion).
- **Approval fatigue** — if a human gate exists, per-action approvals degrade (93% auto-approve); deterministic policy hooks (deny-list, cost gate, sandbox) beat probabilistic supervision. Claude Code's own numbers show ~17% of risky actions slip a classifier.

## 5. Directly transferable to Hngh (SBCL harness, cost-gated, planner → squad → test → regenerate)

Concrete, in order of leverage:

1. **Your cost gate is a PreToolUse hook.** Gate every squad tool call and every model query on the weekly budget *before* execution (Claude Code hook semantics); add per-task step cap and per-task token budget as independent circuit breakers (AutoGPT postmortem pattern). Check the gate in the harness, never in the prompt.
2. **Make the test verifier richer than "target test passes":** run regression suite + a generated reproduction test (Agentless), accept only all-green, and on failure **revert and regenerate with a Reflexion artifact** — squad writes "what failed, why, what I'll change" into OptMem/dispatch tree before the next attempt. Cap attempts at ~3-5 per sub-task with an explicit escalate-to-planner path (self-healing prototype's revert-3-then-escalate).
3. **Planner = localization stage.** Agentless's finding (localization is where accuracy lives, and it's cheap) maps directly: the planner reads the roadmap, but its real job is *narrowing the edit surface* (files → functions → lines in Hngh's own tree) before dispatching. That keeps squad context small and cost low.
4. **Structured artifact hand-off between stages** (MetaGPT SOP): planner emits a spec/dispatch-tree node; squad emits tests+patch+reflection; verifier emits a pass/fail report. No free-form chatter across stages — artifacts are the interface.
5. **Keep failed predictions, not just failures:** reuse the failed patch + test output as the seed of the next attempt (Self-Debugging's sample efficiency) instead of regenerating from scratch.
6. **Event-sourced everything** (OpenHands): your beans/event-bus log is already replayable; make sure a squad run can be replayed deterministically (fixed seeds, pinned model+config) so a "fix" that passes is reproducible before it touches the trunk — this is what makes self-modification of Hngh itself survivable.
7. **When Hngh modifies Hngh:** the only safe order is test-first (write the failing test → let squad make it pass → run full suite → only then merge to the git-backed dispatch tree), with the harness's own budget gate guarding the loop that guards the loop.

**Uncertainty flags:** Codex-1's 72.1%/83.8% SWE-bench numbers and the $50k-loop fleet math are third-party blog figures, not vendor-audited; Agentless's 32%/$0.70 is the paper's own claim vs. leaderboard baselines at submission (Oct 2024) and has since been surpassed by newer models — the architecture lesson stands, the number doesn't. AutoGPT's loop pathology is well-documented; the specific dollar amounts in blog posts are illustrative.
