## Findings

1. **The violation class is a framing defect, not a throughput defect.** "Research-continuous-not-batch" is violated when a beat, summary, or operator message narrates the line as periodic/batched ("this batch," "today's round") rather than as an always-in-motion process on idle hosts. The class is observable in session text; it does not require operator judgment to *detect* — only to *act on*. This is what makes it a candidate for a mechanical steer-vs-die rule.

2. **The observable decision inputs already exist in the line-state schema.** The beat header itself carries the needed fields: `state` (expanding → contracting), `model`, `wall_s`. The TSV per-line state plus per-beat wall time and the presence/absence of a state transition are sufficient signals. **UNVERIFIED:** whether `research-lines.tsv` literally includes a per-beat artifact or wall-time column; one prior-art pointer ([[sources/LES-fail-20260915-Does-the-research-lines-tsv-schema-inclu]]) appears to be exactly a lesson about the TSV schema, suggesting this question was previously investigated — contents not verified here.

3. **Ad-hoc judgment fails in a predictable direction.** The line's OPEN statement records that steer-vs-kill is "judged ad hoc per session." The recurring failure mode (consistent with the vault's LES-fail-* lesson pattern) is that stalls get steered indefinitely — continuity framing makes every session feel "in motion," so nothing ever dies. A threshold rule exists to make death the *default* on evidence of non-motion, with steering as the exception that must be earned by observable output.

4. **Calibration anchor from the line's own data.** The only concrete stall signal in the record is this line's prior beat: `wall_s: 19.0` — a very short beat that announced exploration but recorded no findings, no state transition within the beat (state change was declared in the header, not earned by output), and no new artifact. That is a prototype instance of a die-worthy stall: motion was *asserted*, not *demonstrated*.

## Recommendation: the threshold rule

**Stall test (per stalled session, evaluated automatically):** a session is *stalled* if its most recent beat shows (i) no state transition, (ii) no new artifact or line-state delta, and (iii) `wall_s` below the line's rolling median beat time (i.e., below-engagement effort).

**Decision rule:**
- **DIE (automatic, no operator judgment):** the session is stalled **and** the beat text contains the research-continuous-not-batch violation class (batch framing, or continuity asserted without demonstrated motion). Two independent failure signals — no demonstrated motion *and* misframing of motion — convert to termination.
- **STEER (automatic, exactly one steer):** the session is stalled but violation-free, or violation-flagged but demonstrably productive (artifact/state delta present). The steer must name the missing signal ("produce artifact or transition, or this line dies next beat").
- **DIE on second consecutive stall regardless of framing.** One steer per stall episode, never two. This is the anti-indefinite-steering clause, calibrated against finding 3.

**Calibration parameters** (to be tuned against the TSV history rather than asserted): the wall_s floor (proposed: line rolling median), and whether violation detection is lexical (batch-framing phrases) or operator-tagged. **UNVERIFIED:** no historical TSV data was available in this transition to fit these parameters; the rule above is structurally specified but numerically uncalibrated.
