# Crystallization: ledger-sync commit race (hngh d34ba58)

_state: contracting -> contracted (final) | line: ledger-sync commit race — untracked docs/ file swept into machine commit before lane staging_

## Line question (as posed)

Does the ledger-sync commit path landed in hngh commit `d34ba58` — identifiable by its `docs: machine ledger sync — N changed file(s)` message pattern — still permit a new untracked `docs/` file to be machine-committed before its owning lane stages it?

## Answer

**Yes.** The line's consistent finding across its expansion and contraction is that `d34ba58` added *identifiability* (a recognizable commit-message pattern for machine sync commits) but no *prevention*: nothing in the sync's commit path, as characterized in the prior material on this line, excludes an untracked `docs/` file from being swept into a machine commit before a lane stages it. The race window stands.

## Findings (lasting record)

**F1 — The sync emits identifiable machine commits.**
Landed as hngh `d34ba58`, the ledger-sync path produces commits matching `docs: machine ledger sync — N changed file(s)`. This gives lanes and auditors a reliable post-hoc signal for "this commit was made by the machine sync, not a lane."

**F2 — Identifiability is not exclusion.**
The message pattern constrains nothing at commit time. An untracked `docs/` file — authored by a lane mid-task, or by anything else with write access — can be included in a sync commit before its owner stages it. The pattern tells you the race *happened*; it does not shrink the window.

**F3 — The race has three bad outcomes, all provenance-corrupting.**
Lane writes file → sync ticks → file is machine-committed → lane's subsequent stage/commit either (a) no-ops against an unexpectedly clean tree, (b) double-commits, or (c) conflicts. In every branch, the file's first committed author of record is the machine sync, misattributing provenance — directly at odds with the authority/evidence-ledger design intent recorded in the vault ([[concepts/evidence-ledger]], [[sources/SRC-2026-08-24-021]]).

**F4 — The fix space is well-understood and cheap at the low end.**
Narrowing the sync's pathspec to an explicit ledger manifest (R1) eliminates the race for non-ledger files with no protocol change. Stronger guarantees (claim-before-write, freshness guards) require coordination between lanes and the sync but are architecturally consistent with designs already in the vault.

**F5 — Honesty boundary on kernel internals.**
This line ran without live shell access during its contraction beats. The exact pathspec the sync uses, and the exact filename(s) of the sync script/hook and its scheduler entry inside `[redacted path] (and any hngh-automation companion), were **not verified** during this line. All recommendations that depend on the current implementation shape are conditional on that verification. This line asserts nothing about specific kernel filenames.

## Recommendations (final form)

| # | Recommendation | Type | Cost | Status dependency |
|---|---|---|---|---|
| R1 | Narrow the sync's pathspec to an explicit ledger manifest (ledger TSV/MD + indexes); exclude any `docs/` path not in the manifest | Sync-side | Low | **[verify]** current pathspec in the hngh kernel sync script/hook |
| R2 | Claim-before-write: lanes register intent (lockfile / staging record / `pending` ledger row) before writing a new `docs/` file; sync refuses files matching claims it doesn't own | Lane + sync | Medium | Builds on vault's evidence-ledger design |
| R3 | Lane-side reconciliation: on stage failure or unexpected clean tree, `git log --grep='machine ledger sync'` for the target path; treat a match as a benign prior commit to adopt, not an error to retry | Lane-side, stopgap | Low | Uses only what `d34ba58` already guarantees |
| R4 | Freshness/ownership guard inside the sync: refuse `docs/` files newer than the sync lane's last heartbeat or claimed per R2; log refusals to the ledger | Sync-side | Medium | Depends on R2's claim registry for full effect |
| R5 | Sandbox-only repro/regression test: throwaway clone + artificial sync tick; never against the live ledger | Process | Low | Per [[sources/debug-repro-sandboxes-only]] |

**Sequencing:** R3 is deployable immediately with zero kernel change. R1 is the highest-value permanent fix. R2+R4 together convert "identifiable misattribution" into "prevented misattribution" and should land as a pair. R5 gates any claim that a fix works.
