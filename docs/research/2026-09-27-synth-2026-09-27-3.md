### Core Research Question

> What rule should gate admission of stalled sessions instead of ad hoc per-session judgment?

This is asking for a **deterministic policy** that replaces human discretion when deciding whether to:
- **Steer**: redirect a stalled session toward recovery (retry, re-prompt, escalate)
- **Die**: terminate the session cleanly (abort, failover, discard)

## Findings

### 1. The Problem: Ad Hoc Judgment is Unreliable

From the prior material, the core issue is that per-session judgment for stalled sessions introduces:
- **Inconsistency**: Different sessions get different treatment for similar stall patterns
- **Latency**: Human-in-the-loop decisions add delay to recovery
- **Error**: Bad judgment can worsen the stall (e.g., retrying a fundamentally broken session)

The `session-budget-burn-prevents-discretionary-plan-selection` synthesis suggests that when budget resources are consumed by burn patterns, there's no room left for discretionary decisions — meaning the system is already at a point where it must make automatic decisions.

### 2. The Tool Admission Workaround Pattern

The `tool-admission-workaround` concept (2026-08-24) suggests there's already a pattern for handling admission decisions. If this pattern exists, it likely involves:
- A threshold-based gate for tool/session admission
- Possibly a scoring mechanism
- Possibly a fallback to default behavior when the gate can't decide

### 3. Session Salvage as a Recovery Mechanism

The `session-salvage` concept (2026-08-24) suggests there's already a salvage mechanism. The question is: what triggers salvage vs. termination?

### 4. Delegated Subagent Steering

The `delegated-subagent-steering` synthesis (2026-09-07) suggests that steering can be delegated to subagents. This implies:
- Steering decisions can be automated

## Recommendations

### Recommendation 1: Define a Steer-vs-Die Threshold Rule

**Rule**: A stalled session should be **steered** if it meets recovery criteria, and **died** if it meets termination criteria. The rule should be deterministic and based on measurable signals.

**Steer criteria** (admission to recovery):
- Stall duration is within recoverable bounds (e.g., < N seconds of no progress)
- The session has not exhausted its budget/resources
- The stall pattern matches known recoverable patterns (from `session-salvage`)

**Die criteria** (admission to termination):
- Stall duration exceeds recoverable bounds
- The session has exhausted its budget/resources
- The stall pattern matches known unrecoverable patterns
- Drift is confirmed (from `LES-fail` research)

### Recommendation 2: Implement a Threshold Gate

Based on the `tool-admission-workaround` pattern, implement a gate that:
1. Monitors session health signals (progress, resource usage, drift)
2. Applies the steer-vs-die threshold rule
3. Routes the session to either recovery or termination

### Recommendation 3: Delegate to Subagents

Based on `delegated-subagent-steering`, delegate the threshold evaluation to a specialized subagent that:
- Has access to session history and patterns
- Can make consistent decisions
- Logs decisions for audit

### Recommendation 4: Budget-Aware Steering

Based on `session-budget-burn-prevents-discretionary-plan-selection`, ensure that steering decisions account for remaining budget:
- If budget is low, prefer termination (die) to preserve resources
- If budget is available, prefer steering (recovery) to maximize value
