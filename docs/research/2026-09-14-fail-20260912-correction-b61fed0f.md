## Findings

**F1 — Symmetric failure ⇒ shared parent defect (the load-bearing evidence).**
The operator correction `b61fed0f` reports the breakage as *both sides*. That symmetry is the diagnostic anchor. Two independent per-pane bugs would produce asymmetric symptoms (one pane scrolls, the other does not). A single shared layout container that fails to establish a scroll context for its children produces exactly the observed symmetric breakage: content overflows the viewport, the page itself scrolls (or appears to), and neither pane owns an internal scroll region. This collapses the prior beat's three findings into one primary hypothesis rather than two parallel defects. *Grounded in the line's own evidence (the correction text); no codebase access required.*

**F2 — The repair is a containment-chain gap, mechanism-agnostic.**
For either pane to scroll internally, the layout must satisfy three conditions simultaneously: (a) a **definite height** on an ancestor of the panes (e.g. `height: 100vh − <chrome>` or `flex: 1` inside a full-height column), (b) an intermediate row that does not grow past its box (`overflow: hidden`, or the row itself constrained), and (c) each pane child carrying its own scroll context (`overflow-y: auto`) *and* permitted to shrink below its content size. The most commonly missing property in this exact pattern is the child's ability to shrink — in flexbox that is `min-height: 0` (the default `min-height: auto` pins a flex item to its content height); in CSS grid the analogous lever is the item's automatic minimum size, which `overflow` other than `visible` resets. I state this as **standard web-platform behavior** (well-established layout semantics), *not* as a claim grounded in any specific hngh file — I cannot verify which display mechanism (`flex` vs `grid` vs block-with-explicit-heights) the observatory actually uses from here. The invariant is mechanism-agnostic: *each pane needs its own scroll context, which requires a definite ancestor height plus overflow handling that stops content from pushing the layout past the viewport.*

**F3 — Unbounded transcript DOM is a contributing factor, not an independent bug.**
If the right pane renders full transcript text without a height cap or virtualization, its intrinsic height exceeds the container. Even with correct `overflow-y: auto` on the child, a parent lacking an explicit height constraint lets the flex/grid sizing let the child grow. The repair is the *same* containment chain as F2; the transcript pane may additionally need `max-height` or `flex: 1; min-height: 0`. It does not change the disposition — it is absorbed by the single-site fix.

**F4 — Virtualization is a red herring for this defect.**
The prior beat noted that >50 sessions without virtualization causes jank. That is a *performance* concern, not the cause of "scrolling is broken" as a *functional* failure. It must not be conflated with the scroll fix. If it surfaces after the fix lands, it is its own disposition (see Open Threads).

## Disposition: **fix** (closes the line)

The defect is a CSS containment gap in **one shared layout component**, not two independent bugs and not a data/virtualization problem. It is bounded to a single site, low-risk, and high operator-facing impact — the observatory is unusable for long session lists or long transcripts, which is precisely the scenario that motivated it. Parking would leave a functional breakage in an operator-facing tab with no path to closure. **Fix** is the disposition that closes this line; the fix is one commit's worth of work (see Recommendations).

Once located, apply the containment chain:

   ```
   [tab root]     → definite height: 100vh − <chrome>, or flex: 1 in a full-height column; overflow: hidden
     [flex/grid row] → display: flex (or grid); height: 100%; overflow: hidden
       [left pane]    → fixed/`flex: 0 0 <w>`; min-height: 0; overflow-y: auto
       [right pane]   → flex: 1 1 0% (or grid track); min-height: 0; overflow-y: auto
   ```

   The decisive properties are almost certainly `min-height: 0` on both pane children and `overflow-y: auto` to create the scroll context, plus a definite height on the tab root. If the tab root already has `height: 100%`/`flex: 1`, only the child properties are needed; if not, add the explicit height too.

2. **Do not bundle virtualization into this fix.** Land the containment repair alone. Treat >50-session jank as a separate line if it reproduces post-fix (F4).
