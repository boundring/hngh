## Findings

### Finding 1 — Schema failures are recurrent, not one-off

Two header-row failures occurred within an eight-day window: `LES-fail-20260915-Does-the-research-lines-tsv-schema-inclu` and the current seed (`fail-20260922-Does-the-research-lines-tsv-schema-curre`). This recurrence indicates that header drift is a systemic issue in the research-line harvest pipeline, not an anomaly caught by human vigilance.

### Finding 2 — Column-arity drift is the likely failure signature

The prior expansion identified that column-count drift (not merely header-name drift) is the probable failure mode. A Level 1 check (exact header match) is necessary but insufficient; Level 2 checks (field arity, required-field non-emptiness) are required for robust integrity.

### Finding 3 — The line state file is the coordination substrate

`research-lines.tsv` is the coordination substrate for the continuous research process. Blocking unrelated commits would fight the workflow. The hook must be scoped to staged files containing this specific file.

### Finding 4 — Portability trap between hook delivery mechanisms

Git hooks (`.githooks/pre-commit`) are local and not versioned; pre-commit frameworks (`.pre-commit-config.yaml`) are versioned but require setup. The choice affects reproducibility across hosts.

## Recommendations

### R1 — Implement a two-tier header check in `research-lines.tsv`

**Action:** Add a pre-commit hook that validates the first line of `research-lines.tsv` against a pinned golden header.

**Implementation:**
- Pin the golden header as a byte-for-byte string in a separate file (e.g., `research-lines.tsv.header.gold`) or as a constant in the hook script.
- The hook should fail the commit if the first line does not match exactly (including tab separators, no spaces-as-tabs).
- This implements Level 1 from Finding 2: catches rename/reorder.

**Verification gap:** The current golden header and whether `research-lines.tsv` exists in the hngh repository tree require filesystem inspection.

### R2 — Add column arity and field sanity as additive checks

**Action:** Extend the hook to check that every data row has the same number of tab-separated fields as the header, and that required fields (line slug, lifecycle state) are non-empty.

**Implementation:**
- Parse the header to get expected column count.
- For each data row, split on tabs and verify field count matches.
- Check that fields matching known required-field names are non-empty.
- Emit warnings (not failures) for arity issues during a grace window.

**Verification gap:** Actual column names and required-field definitions require inspecting the file.

### R3 — Scope the hook to staged files only

**Action:** Run the check only when `research-lines.tsv` appears in the staged file list.

**Implementation:**
- In the hook script, check `git diff --cached --name-only` for `research-lines.tsv`.
- If absent, exit 0 immediately (no-op).
- If present, run the full validation suite.

**Verification gap:** Whether the hngh repository already has a `.githooks/` directory or a `.pre-commit-config.yaml` requires tree inspection.

### R4 — Choose hook delivery mechanism with portability in mind

**Action:** Decide between a Git hook script (`.githooks/pre-commit`) and a pre-commit framework (`.pre-commit-config.yaml`).

**Implementation:**
- If the hngh repository is already using pre-commit (check for `.pre-commit-config.yaml`), add the hook as a new hook in that config.
- If not, create a `.githooks/pre-commit` script in the repository root.
- Document the choice in the repository's README or CONTRIBUTING file.

**Verification gap:** Current hook infrastructure in the hngh repository requires tree inspection.
