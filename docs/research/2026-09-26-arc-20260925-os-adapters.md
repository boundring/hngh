## Findings

**F1 — The line itself demonstrates the gap it studies.**
The prior beat emitted dozens of probe *plans* against the hngh repo and vault, and none returned observable output into the record. The harness adapters are static in exactly the way the research question names: they can *express* an executable probe but nothing closes the loop — no execution result, no observation artifact, no downstream state change. This is direct, in-line evidence (the truncated 2026-09-26 beat) that the missing capability is not "permission to run" but "a path by which a real probe result lands back in the line's artifacts."

**F2 — A two-tier capability model is implied by the prior art.**
The vault pointers sketch the shape of an answer:
- The *LES-fail* research lessons (`[[sources/LES-fail-20260915-Has-R1-systemctl-status-list-timers-jour]]`, `[[sources/LES-fail-20260915-Does-the-obs-2026-08-25-hngh-automation-]]`) reference `systemctl status`, `list-timers`, and journal inspection — i.e., **read-only system observation** was the probe surface under study, and it *failed*, which is why there are lessons named "LES-fail."
- `[[sources/hngh-ceremony-loop-mechanics]]` is summarized as "closed vocabularies, path position[al]" mechanics — consistent with a harness that validates actions against a closed command vocabulary and positional path constraints, denying anything outside it (fail-closed).
- `[[sources/obs-2026-08-25-hngh-automation-overnight-harness-built-verified-enabled]]` records that an automation harness was built, verified, and enabled — so a working harness exists or existed, but per F1 it does not route probe stdout into the research line.

**F3 — The executable-adapter pattern exists externally but is unverified here.**
`[[sources/lobehub-agent-harness-cloud-api]]` (agent harness with OAuth Cloud API, WebMCP, credential handling) points at how external projects make adapters executable: a credentialed, brokered execution channel. Whether any of that pattern is adopted or adoptable in hngh is **not verifiable from this record** — I have no repository file confirming it, and I will not assert it.

**F4 — Fail-closed execute() and executable probes are not in tension; the vocabulary split resolves it.**
Combining F2's pieces: probes become executable when the allowlist is split into (i) a **probe tier** — read-only, closed-vocabulary, path-positional commands of the `systemctl status` / `list-timers` / journal-read class, whose outputs are captured as observation artifacts — and (ii) an **execute tier** that remains deny-by-default for anything mutating. The ceremony note's "closed vocabularies, path positions" is the enforcement mechanism that lets tier (i) open without tier (ii) loosening. This is a synthesis of the note titles, not a reading of hngh source code.

## Recommendations

1. **Close the capture loop before widening any allowlist.** The demonstrated failure (F1) is that probe results never enter the record. The minimal real capability is: execute an allowlisted read-only probe, write stdout to an observation note in the vault (the `obs-YYYY-MM-DD-*` pattern already exists per prior art), and link it into the line state. Without this, any allowlist widening is inert.
2. **Codify the probe tier as a manifest with closed vocabularies and positional path rules**, mirroring the mechanics the ceremony note describes. Start from exactly the command class visible in the LES-fail lessons: `systemctl status`, `systemctl list-timers`, read-only journal queries. Deny everything else by construction, not by review.
3. **Leave execute() untouched.** The question's constraint — allowlisted, fail-closed — is satisfied by construction if the probe tier is read-only and separately allowlisted. Do not negotiate the execute tier on this line.
4. **Verify before extending.** Before recommending any credentialed/brokered execution (the lobehub pattern), someone with repository access must confirm what hngh actually implements. This line has never verified a single file beneath `[redacted path] that is the first probe the newly-executable adapter should run — and its output should be the first artifact proving the loop is closed.
