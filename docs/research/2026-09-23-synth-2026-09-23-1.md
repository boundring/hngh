## 3. Assessment of the core question

The question presupposes a gap: that harvest-stale detection fires, but no ledger transition exists to record the steer-vs-die decision, so the loop doesn't close. For this to be answerable, three facts are needed:

- (a) the current transition vocabulary in `patrol/ledger/transitions.tsv`;
- (b) the transition(s) the guardrail actually emits or expects, per the full text of `patrol-20260922-research-ledger-harvest-stale.md`;
- (c) the steer-vs-die threshold definition, per `research-line-lifecycle.md`.

Only the *locations* of (a), (b), and (c) are confirmed. A priori, given that transitions are tabulated in a TSV, the burden of proof should be on *adding* a transition: the default hypothesis is that an existing transition (e.g., a generic lifecycle terminal transition) can be reused with harvest-stale as trigger context, and a schema change is warranted only if the steer-vs-die decision carries structured payload no existing transition can hold. **This remains a hypothesis, not a finding.**
