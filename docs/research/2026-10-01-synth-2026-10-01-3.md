## What can be asserted from git semantics alone (no repo access needed)

The hypothesis embedded in the line — *"staged promptly by lanes blocks machine commits"* — is only true under a specific sync-script design. Git semantics give three possible behaviors for the hourly sync when a lane has staged an untracked `docs/` file:

1. **Guarded abort (hypothesis holds).** If the sync begins with a cleanliness check such as `git diff --cached --quiet || exit 0`, a lane-staged file makes the index non-empty and the machine commit is deferred. This is the only design under which prompt staging *blocks* the race.
2. **Whole-index commit (race lost silently).** If the sync runs `git add <ledger path> && git commit -m "sync"`, the commit sweeps in *everything already staged*, including the lane's `docs/` file. The lane's work is then attributed to a machine commit — the exact failure this line exists to prevent. Prompt staging here makes things *worse*, not better.
3. **Path-scoped commit (race neutralized, staging irrelevant).** If the sync commits only its own paths (`git commit -m "sync" -- <ledger paths>`), lane content is never swept regardless of staging timing — but then "staging blocks machine commits" is not the mechanism doing the work.

So the line's confirmation question reduces to: **which of these three shapes does the hourly sync in hngh-automation actually have?**

## Recommendations (contracted, applicable to hngh/hngh-automation)

1. **Adopt belt-and-suspenders in the sync script: path-scoped commit + staged-index guard.** Do not rely on behavior (1) alone, because it conflates "lane is mid-flight" with "sync should skip." Recommended shape: (a) `git add` only the machine-owned ledger path(s); (b) refuse to commit if the staged index contains anything *outside* those paths — i.e., check `git diff --cached --name-only` against an allowlist before committing. This both prevents sweep-in and makes lane activity observable in sync logs.
2. **Make the lane-side contract explicit and immediate.** Lanes must run `git add` (or `git add -N` for intent-to-add on files whose content isn't final) on new `docs/` files at creation time, not at task completion. The blocking guarantee only exists during the window the file is staged; an unstaged untracked file is invisible to a staged-index guard.
3. **Declare path ownership in one place.** Machine-owned: the ledger file(s) the hourly sync appends to. Lane-owned: `docs/` and any research artifacts. Write this ownership map into the sync script's allowlist and into the lane instructions, so the guard in recommendation 1 is a config diff away from audit.
4. **Add a regression test, not just a policy.** Script the exact scenario this line is named after (lane stages file → machine commit either aborts or ignores) and wire it into the CI or nightly run of `hngh-automation`.
