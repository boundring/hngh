## Findings

**F1 — The orthogonality framing is correct at the category level and incorrect at the system level.**
"G0 inspection ⊥ audit-integrity" holds as a statement about *failure domains*: G0 gates content admission, integrity constraints gate trail fidelity, and each can fail while the other passes. But it fails as a statement about *system structure*, because G0 verdicts are recorded in the audit trail and therefore inherit the trail's integrity requirements. An unprotected trail can fabricate a passing G0 verdict after the fact. The crystallized formulation, recommended for adoption in hngh and hngh-automation documentation, is:

> G0 inspection and audit-integrity are orthogonal *mechanisms*; they are *coupled* through the trail. Every G0 verdict recorded in the trail is only as trustworthy as the trail's tamper-evidence.

**F2 — The missing verification steps are five, and they are content-independent.**
The checklist below was derived without reference to the record's text and survived contraction unchanged. It represents the minimum set for a verifiable audit trail in a store of the kind hngh operates. Whether the `fail-20260918` record names all five, a subset, or none is an open thread (T1); the checklist's validity does not depend on that.

**F3 — Two prior vault observations bound the threat model concretely.**
- `obs-2026-08-26-hngh-create-run-transport-fault-on-missing-store-dir` shows the hngh store layer surfaces *structural/transport* faults loudly. Loud transport failure and silent tampering are complementary threats; only hash chaining (R2) addresses the latter.
- `timezone-local-vs-utc-rendering-fabricates-missing-commits` demonstrates byte-level rendering divergence of the same logical fact — the concrete failure mode that makes canonicalization (R5) a prerequisite rather than a refinement.

## Recommendations

- **R1 — Write-time content digest.** Hash each audit/record entry over its canonical serialization *before* admission; store the digest adjacent to the entry. Ground truth for all subsequent checks.
- **R2 — Hash chaining.** Each entry's digest incorporates the previous entry's digest. Per-entry checksums alone detect only mutation; chaining is required to detect deletion and reordering.
- **R3 — Manifest root digest.** One digest per run/session over the whole trail, enabling a cheap "has anything changed" check without re-reading every entry.
- **R4 — Documented verification procedure.** An explicit recompute-and-compare step, runnable independently of the writer. For hngh-automation this should be a standalone command, not a flag in the write path. A checksum never recomputed is a comment, not a constraint.
- **R5 — Canonicalization rule first.** Define the byte-level canonical form before specifying any hashing: pin timezone (UTC), field order, and encoding. Without this, R1–R4 hash rendering noise rather than content.

Ordering note: R5 is a prerequisite for R1; R1 for R2; R2 for R3; R4 depends on all four. Implementation can proceed R5 → R1 → R2 → R3 → R4 with no rework.
