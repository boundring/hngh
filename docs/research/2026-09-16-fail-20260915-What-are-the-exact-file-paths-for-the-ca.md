## Recommendations (final form)

- **R1 — Close the question with two commands.** From `/home/bricker/Projects/etc/hngh`: `grep -rln "verdict" --include="*.py" .` to pin the canonical rule; then locate the automation side (`ls .github/workflows/` + `grep -ln "verdict" .github/workflows/*.yml` if colocated, or the equivalent in the hngh-automation checkout once T3 resolves its location), and note whether the copy is an inline `run: |` block or a script invocation.
- **R2 — Eliminate the embedded copy.** Regardless of where the files turn out to live: have CI import the kernel's verdict function (editable install or pinned dependency) instead of duplicating logic. If isolation forbids import, a thin wrapper that fails loudly on divergence — never a silent duplicate.
- **R3 — Tripwire any remaining duplication.** Hash- or diff-check the embedded logic against the kernel source as a blocking CI step, so drift becomes a build failure rather than a latent bug.
- **R4 — Version the rule.** A `VERDICT_RULE_VERSION` constant beside the canonical implementation, emitted in CI logs, makes future drift detectable from logs alone.
- **R5 — Write the resolution back.** When R1 lands, update `[[sources/verdict-rule-drift-two-surfaces]]` and `[[entities/hngh]]` with verified paths and the chosen sync mechanism, so no future line re-derives this.

R2–R4 are structural and hold under every plausible layout; R1 and R5 are the closure steps.
