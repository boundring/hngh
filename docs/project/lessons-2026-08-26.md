# Lessons — 2026-08-26 overnight loop

What the overnight run of the evolutionary UI loop and the scheduled-jobs
investigation left behind that transfers beyond its own night.

## (a) Fail-first grading

Capture before taste. Each dashboard/operative slice was captured, a
local vision pass critiqued it, the finding went to the ledger
(`docs/project/ui-grades.md`), and the next slice was carved from the
finding — not from an opinion.

The first grade was 4/10 with the finding **"title/header text:
OVERVIEW commands sessions …"** — a real data-dump bug in
`dashboard-tui`, where the header was leaking raw live telemetry
instead of a clean label. The machine caught a defect, not a style
preference, because the grader reads pixels/accessibility and holds a
fixed rubric. Fail-first means the low grade is the signal that drives
the mutation, and a passing grade is never assumed, only measured.

## (b) Evolutionary art

The operative is bred, not drawn once. The fitness signal per
generation is a paired operator + vision critique; a deterministic
generator (`scripts/evolve-operative`) mutates a small art-parameter
pool; and `docs/design/operative-frames.md` pins the frame catalog so
each generation is byte-regressed against the last — a mutation never
silently rewrites an accepted aesthetic.

The loop is: capture → critique → ledger → mutate → re-measure. The
generator stays deterministic (same seed, same frame) so a grade maps
to a reproducible artifact, and the byte-regression is the guard that
"the operative changed" is always an explicit, reviewed change, never
an accidental drift.

## (c) Parallel lanes + governance isolation

Multiple workers committed the same tree overnight without
cross-contamination. The reason is the candidate contract: every
validated commit names **explicit paths** — `ceremony-drive` binds only
the files it is given, gathers fresh evidence over exactly those
paths, and commits only them. A worker's dirty sibling file (the
`ui-grades.md` the grading loop owns) is never staged by another lane.

Lesson: the governance loop's explicit-path candidate is what makes parallel
logical ownership safe on one tree. Two workers editing disjoint paths
never collide because neither ever stages "everything"; each binds the
narrow manifest it shipped. This is the mechanical answer to "how do
N agents share one repo without a lock."

## (d) The scheduled-jobs lesson

"All cancelled" looked like dead automation. It was a beacon-semantics
bug. The 42/42 `cancelled` store runs were the automation repo
deliberately closing every recorded run `cancelled` in
`lib/hngh-record.sh` — a best-effort activity beacon, not a failure.
The schedule was healthy: 7 systemd user timers, all active, every job
`Result=success`, hourly snapshots and digests present.

Lesson: when a view says "dead", verify the **trigger layer before
trusting the view**. Check the timer/cron state, the last-run
timestamps, and the writer that produced the rows — the dashboard is a
renderer of evidence, not the evidence itself. After the investigation,
exit-0 runs close `evacuated` and all seven jobs beacon, so the view and
the schedule agree.

## (e) Doc-soon

The overnight records (`docs/records/2026-08-26-*.md`) were committed
the same night the work landed — the OSD/dashboard record, the
scheduled-runs investigation record, and this one. The cost of writing
a fact a day later is archaeology: reconstructing "why" from a diff.
The cost of writing it in the same session is one commit.

Lesson: a record committed the night it happens is a decision; a record
written a week later is a guess. Doc-soon beats doc-later because the
evidence is still warm and the governance loop makes a record cheap.
