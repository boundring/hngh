### What was learned
- SBCL `FORMAT` strings interpret `~` as a format directive — `~/.hngh/` in a FORMAT control string must be escaped as `~~/.hngh/` or the string breaks compilation. Only affects FORMAT control strings, not docstrings.
- Makefile phony targets can't share names with directory targets — `build` as both a phony target and the build directory caused a circular dependency. Fixed by renaming build dir to `bin/`.
- The `hngh:main` symbol must be exported from the `hngh` package for `save-lisp-and-die :toplevel` to find it.
- SBCL standalone binary is ~37MB for the current minimal skeleton (no external deps). Expected to grow as components are added.

#### What was learned
- SBCL `--no-sysinit --no-userinit` doesn't load contrib modules (sb-posix) — use `sb-ext:run-program` or add `(require :sb-posix)` in the Makefile's SBCL invocation
- `&key (var nil var-p)` — when the caller passes `:var nil`, `var-p` is T (the keyword was supplied). This means nil is a valid, intentional value, not "not supplied". Must check `var-p` before using `var` in a cond.
- `use-package` causes name conflicts when the package already has symbols with the same names as the source package's exports. Prefer qualified symbol references in test files.
- `uiop:delete-directory-tree` requires a `:validate` predicate for safety — `:validate #'identity` is the common pattern.

### Decisions made
- D-005: Custom test harness instead of FiveAM — keeping dependencies minimal for M0 skeleton. Can migrate to FiveAM later if the custom harness becomes limiting.
- D-006: Build directory named `bin/` (not `build/`) — avoids Makefile phony/directory name collision.

### Session M0.2: Event Bus (A2)

#### What was done
- Created `src/core/event-bus.lisp` — pub/sub engine with:
  - Topic namespace matching: exact strings, `.*` wildcards (e.g. `"system.*"`), bare `*` (matches everything)
  - Event struct with monotonic IDs, topic, payload, timestamp, source
  - Event journaling: append-only to `~/.hngh/journal/events/YYYY-MM-DD.lisp` (one file per day, auto-rotates on date change)
  - Subscriptions: per-subscriber filter function, persistent tracking (last-event-id for replay), backpressure policies (:block, :drop, :queue with configurable queue-max)
  - Persistent subscription replay: on subscribe, reads journal files and replays missed events matching topic pattern
  - Callback error isolation: if one subscriber's callback errors, others still receive the event
- Created `tests/unit/test-event-bus.lisp` — 11 tests
- Wired into start/stop sequence in main.lisp

#### What was learned
- `READ` from a file returns symbols in the current package context, not the package they were written from. A form `(event :id 1 ...)` written from `hngh.core.event-bus` reads back as `(CL-USER::EVENT :id 1 ...)` when read from `CL-USER`. Fixed by checking by string name rather than `EQ` on symbol identity.
- Journal rotation: the journal file needs to close and reopen when the date changes. The `ensure-journal-open` function handles this by comparing the current date string with the open file's date.

### Session M0.3: State Store (A3)

#### What was done
- Created `src/core/state-store.lisp` — file tree operations with:
  - `read-state`/`write-state` for Lisp data (uses READ/PRIN1)
  - `read-state-string`/`write-state-string` for raw text
  - `delete-state`, `state-exists-p` for file management
  - Parent directory auto-creation on write
  - Journal append/read (append-only, one form per line)
  - File-based cross-plugin locks with TTL: acquire (checks existing lock validity), release (holder-validated), list-locks, release-all-locks (shutdown), expired lock auto-reclamation
  - Snapshot (tree hash via SXHASH on file paths and sizes — simple integrity check, not cryptographic)
  - Shutdown releases all locks held by the process
- Created `tests/unit/test-state-store.lisp` — 17 tests (one uses `sleep 2` for TTL expiry test)
- Wired into start/stop sequence in main.lisp (state store shuts down before event bus)

#### What was learned
- SQLite (cl-sqlite) is not available on this system without Quicklisp setup. Used file-based locks as the M0.3 implementation — noted as D-007 for future migration to SQLite when cl-sqlite is available.
- File-based locks need TTL to handle crash recovery (holder crashes, lock stays forever). The TTL-based expiry + auto-reclamation pattern handles this cleanly.
- Lock holder identity matters: `release-lock` only succeeds if the caller matches the holder. This prevents accidental release by the wrong component.

#### Decisions made
- D-007: File-based locks for M0.3 (SQLite deferred). File-based locks work for M0's needs; SQLite migration is a future enhancement when cl-sqlite is available via Quicklisp.
