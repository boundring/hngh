## Squad seat startup fix (opencode model-string naming)

- Diagnosed "opencode members don't start": coder/worker seats set
  `SEAT_MODEL=deepseek/deepseek-v4-flash-0731`. opencode DOES recognize
  `deepseek` as a provider, but only offers simply-named models there
  (`deepseek/deepseek-v4-flash`, `deepseek/deepseek-v4-pro`); `deepseek-v4-
  flash-0731` (`-0731`) is **openrouter's catalog name**, not a deepseek-
  provider name. Since `deepseek-v4-flash` == `deepseek-v4-flash-0731` (deepseek
  serves that as its latest under a simpler name), the bad string never
  resolved and every opencode kick died with `UnknownError: Unexpected server
  error` — the window opened (squad-up reported RUNNING) but the first prompt
  failed on model resolution.
- Two valid routes: `deepseek/deepseek-v4-flash` (deepseek direct API) or
  `openrouter/deepseek/deepseek-v4-flash-0731` (same model via openrouter).
  We use **Flash** because it's the smarter model for now, and default to the
  **openrouter** route because it's usually cheaper — a cost preference, not
  a rule; when deepseek-direct prices lower, it's the valid alternate.
- Auth was fine: `OPENROUTER_API_KEY`/`DEEPSEEK_API_KEY` are exported in
  `~/.hermes/.env` (lines 507/496, sourced by the interactive shell; not in
  the Hermes terminal env — located by name, never printed).
- Verified: `set -a; . ~/.hermes/.env; set +a; opencode run -m
  openrouter/deepseek/deepseek-v4-flash-0731` → `OPENCODE_SMOKE_OK`.
- Fix: coder/worker `SEAT_MODEL` → `openrouter/deepseek/deepseek-v4-flash-0731`
  in `~/.hngh-night/squad-seats.conf` (with corrected NOTE comments). Hermes
  CLI seats correctly keep `deepseek/...` (Hermes maps it). `squad-up --list`
